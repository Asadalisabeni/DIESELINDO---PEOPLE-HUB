# Payroll calendar and periods

A payroll group belongs to one legal entity and stores the monthly frequency, entity timezone and currency, proration basis, cutoff start day, cutoff end day, payment day, and payment-date adjustment policy. These fields are configuration, not executable assumptions hidden in source code. Employee membership is independently effective-dated; overlapping membership in any payroll group is rejected so a person is not silently included twice. Cross-entity employee and group combinations return a not-found boundary.

Each period records a stable period key, run purpose, payroll start and end, attendance cutoff start and end, and payment date. It also copies the current payroll-group configuration into a calendar snapshot. Later group edits therefore cannot silently rewrite the evidence used to open an existing period. Phase 10 accepts monthly, off-cycle, THR, bonus, and final-settlement period types, although the delivered proration and salary engine remains a foundation that requires UAT for every non-regular business process.

Calendar-day proration counts service dates inclusively. Working-day proration resolves the employee's effective employment history, holiday coverage, explicit employee schedule assignment, and department, branch, or entity schedule fallback for each date. A missing effective schedule is a blocking configuration error rather than a guessed work pattern. Join and termination dates cap service dates inside the period. A run with corrected source data receives the next immutable version; the period may be `open` or `processing` when that new draft is created.

Operational owners must approve cutoff semantics, payment-date adjustment, holiday handling, joiner and leaver policy, final-settlement timing, and the authoritative attendance window. The current foundation does not automatically derive dates from the day-of-month configuration because month-end, holiday, banking, and entity-specific rules require an explicitly reviewed calendar. Production creation should therefore be controlled through an operating checklist and reconciled against Finance's approved calendar.
