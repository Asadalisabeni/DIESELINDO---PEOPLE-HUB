# Phase 10 scope and security

Phase 10 establishes the controlled payroll foundation for monthly, off-cycle, THR, bonus, and final-settlement run types. The delivered workflow covers effective-dated salary components, employee salary versions, payroll groups and memberships, payroll periods, versioned calculation runs, immutable employee snapshots, detailed payroll items, and validation findings. It does not implement statutory PPh 21 or BPJS formulas, overtime wage formulas, final review, approval, lock, reopen, bank-file generation, payslip publication, or accounting posting. Those capabilities require later approved phases and must not be inferred from a `validated` Phase 10 run.

Access is both permission- and legal-entity-scoped. Payroll Administrator can prepare and validate but cannot perform Finance review or final approval. Finance Reviewer independently approves salary versions and has read/review permissions without preparation rights. Company HR can inspect salary information but cannot prepare payroll. Auditor access is read-only and may export only within an effective view scope. Super Admin has capabilities but never receives an implicit row-scope bypass. Every write path resolves the legal entity and requires an effective `manage` grant; cross-entity identifiers fail closed.

Salary reasons, bank snapshots, and finding details are encrypted at rest. Exported registers omit full account numbers, confidential salary reasons, and encrypted finding evidence. Audit events contain public identifiers, configuration metadata, counts, checksums, and lifecycle actions rather than secret values or compensation amounts. The browser UI also prevents salary-only viewers from forcing payroll-run evidence through a query parameter. Application models prevent update or deletion of approved salary histories, salary lines, run employee snapshots, payroll items, validation findings, and validated runs.

Production use still requires identity recertification, segregation-of-duties review, retention and legal-hold rules, database backup and restore rehearsal, queue and audit monitoring, export handling controls, and UAT with real scoped roles. No production credential is embedded in code, documentation, fixtures, logs, or Git history.
