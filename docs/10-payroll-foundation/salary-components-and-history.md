# Salary components and employee history

Salary components are legal-entity scoped and effective-dated. A component defines its code, display name, economic type (`income`, `deduction`, or `employer`), calculation type, tax and BPJS eligibility flags, currency, and explicit rounding scale and mode. Phase 10 supports recurring fixed-monthly and daily-rate lines, unpaid-leave daily deductions, and overtime meal or transport allowance inputs. Overlapping active versions of the same component code are rejected. Component configuration contains no regulatory percentage, statutory ceiling, or hidden default.

An employee salary change starts as a draft created by an authorized maker and contains one or more component lines using fixed four-decimal strings. The service resolves each referenced component on the proposed effective date, normalizes amount and quantity without binary floating point, derives income and deduction totals, and creates a deterministic SHA-256 version checksum. The confidential reason is encrypted. A different scoped user with `salaries.approve` must approve the draft; the maker cannot approve the same version even when that maker holds both permissions.

Approved versions and their component lines are immutable. A later approved version does not edit the earlier evidence row. Instead, payroll calculation orders the approved versions and derives each logical segment: the next effective start establishes the previous version's logical end unless an earlier explicit `effective_to` already applies. This preserves original checksums while preventing double counting. A version beginning on the same employee/date is rejected, and approval is rejected when a later approved version would make the sequence ambiguous.

The Phase 10 review must confirm component ownership, naming conventions, effective dates, allowed salary line types, rounding policy, and maker-checker assignments. HR and Finance should also reconcile legacy salary records before production import. Taxable and BPJS-eligible flags are descriptive inputs only until Phase 11 supplies verified effective-dated statutory rule sets from current official sources.
