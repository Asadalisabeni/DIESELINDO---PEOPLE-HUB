# Phase 9 — Actual validation and payroll input

Attendance is the source of actual time. Overtime selects exactly one record for the request employee, legal entity, and work date where `is_current` is true. Incomplete and anomalous records are blocked. Check-in and check-out are mandatory, and HR validation cannot run before the planned end. The selected Attendance record identifier is stored on both request and calculation so reconciliation remains reproducible if a later Attendance correction creates another version. Phase 9 does not rewrite Attendance `overtime_minutes`, payroll eligibility, raw events, source payloads, GPS fields, or selfie metadata.

The downstream Overtime payroll input is a reviewed contract, not a wage calculation. Its minimum evidence is request public ID, employee and legal entity scope, work date, day type snapshot, request type, planned minutes, approved minutes, actual minutes, payable minutes, weighted minute hundredths, meal and transport eligibility and configured amounts, immutable rule/version reference and checksum, attendance record reference, Payroll confirmation action, and payroll period key. Encrypted reason and validation text are not part of the contract.

Payroll inclusion is a separate least-privilege Approval step. A Payroll Administrator can confirm eligible units but cannot change calculation rules or HR actual evidence. A Company HR administrator can validate actual evidence but cannot confirm inclusion. Phase 10 must consume this contract through an application query scoped to the payroll run legal entity and period; it must not recalculate from current rules. Reopened or corrected evidence requires an explicit superseding calculation design before production. Reconciliation reports compare planned, approved, actual, payable, and included states and flag missing current attendance, zero payable time, rule checksum mismatch, or missing period confirmation.
