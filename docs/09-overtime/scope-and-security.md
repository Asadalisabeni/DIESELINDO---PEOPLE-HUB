# Phase 9 — Scope and security

Overtime is confidential employment data. Every read and mutation applies capability, actor relationship, current workflow assignment, and effective legal-entity scope independently. An employee sees requests linked to their employee record or created by their account. A Supervisor may create a request only for a current direct report. The generic Approval engine snapshots the resolved manager, active subject-specific delegation, upper-manager fallback, or scoped HR fallback when the request is submitted. It never auto-approves a missing organization path, and a requester cannot approve the request they created.

HR actual validation requires `overtime.validate` plus `manage` access to the request legal entity. Payroll inclusion requires the separate `overtime.include-payroll` capability and managed entity scope. Company HR does not receive Payroll inclusion; Payroll does not receive rule-management authority. Super Admin has capabilities but no implicit business-row scope. Auditor access is read-only and limited to effective entity access.

Reasons, work descriptions, and HR validation notes are encrypted at rest and excluded from CSV, notification payloads, and audit properties. Notifications contain only the public request identifier and translation keys. Calculation snapshots contain policy inputs and arithmetic evidence, not salary data. The module does not store an overtime wage amount. Calculation rows reject update and delete through the application model; corrections require a future explicit superseding workflow. Audit events use public subject identifiers and redacted operational facts. Attendance remains owned by Attendance; Overtime reads only the current normalized record and never mutates raw punches or normalized history.
